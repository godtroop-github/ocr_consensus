# OCR Consensus / OCR 共识处理台

[English](README.md) | [简体中文](README.zh-CN.md)

OCR Consensus 是一个多 OCR 引擎共识处理台，用于将截图、图片或压缩包中的图像批量解析为可审阅、可追溯、可比对、可沉淀基线的结构化结果。

它面向“只有 OCR 原文还不够”的业务场景：系统会保留每个模型的识别证据，叠加确定性规则增强与字段级共识，并提供处理台、结果列表、详情审阅、基线管理和协同提交能力。

> 本 README 中的截图均使用虚构演示数据渲染，不包含真实个人信息、真实企业名称、真实证件号、真实部署地址或客户信息。

## 核心亮点

| 能力 | 说明 |
| --- | --- |
| 多 OCR 引擎 Harness | 多路 OCR 独立执行，保留每一路原始结果、置信度、耗时和执行状态。 |
| 规则增强抽取 | 从噪声 OCR 文本中归一化姓名、脱敏证件号、截图时间、数量字段和任职明细候选。 |
| 字段级共识 | 生成单一可审阅结果，同时保留缺失、冲突、占位、规则加工、弱证据等状态。 |
| 任职明细解析 | 抽取企业名称、经营状态、承担职务、持股比例等明细字段。 |
| 基线管理 | 将复核后的结果保存为持久化基线，支持后续批次比对和字段级裁决。 |
| 证据横向对比 | 横向展示各 OCR 模型字段结果、原始 OCR、置信度、规则标记和图片证据。 |
| 协同收集 | 创建统一提交批次，跟踪人员提交状态，并将合格图片汇入同一 OCR 流程。 |
| 安全辅助模型 | 支持 PP-OCRv6 等辅助/shadow 模型，在不直接替换主共识链路的情况下收集增量证据。 |

## 工作流

1. **收集图片**：通过处理台或协同提交入口上传单图、多图或 ZIP 包。
2. **多路 OCR 执行**：按配置独立运行多个 OCR 引擎，并保留原始输出和方法级元数据。
3. **Harness 规则增强**：清洗页面噪声，归一化脱敏证件号，抽取截图时间、数量字段和任职明细候选。
4. **字段共识决策**：将模型级候选合并为单一结构化结果，并保留可解释的决策信息。
5. **异常审阅**：在看板中筛选字段缺失、字段冲突、方法报错、图片质量问题和任职变化。
6. **保存或比对基线**：将复核后的结果保存为基线，对新批次进行差异比对，并按字段裁决更新。

## 数据模型

| 区域 | 示例字段 |
| --- | --- |
| 基础信息 | 文件编号、文件名、姓名、员工编号、脱敏证件号、截图日期时间、相关企业数、任职企业数、参股企业数 |
| 任职明细 | 序号、企业名称、经营状态、承担职务、持股比例 |
| 共识元数据 | 一致、冲突、缺失、占位、证据补齐、规则加工、辅助证据支持 |
| 方法证据 | OCR 引擎名称、执行状态、平均置信度、抽取字段、原始 OCR 文本、耗时 |
| 复核状态 | 待复核、复核通过、复核不通过、放弃裁决、复核原因 |
| 基线证据 | 基线版本、来源任务、入选图片、图片质量、图片指纹提示 |

## 运行模式

| 模式 | 用途 |
| --- | --- |
| 主 4 路 OCR | 作为共识主来源，具体引擎通过环境变量配置。 |
| 辅助 / Shadow OCR | 运行 `ppocrv6_small` 等辅助模型，用于证据收集或有限字段辅助。 |
| 基线比对 | 将复核后的共识结果与持久化基线逐字段比对，列出差异。 |
| 协同提交 | 支持多人按批次提交图片，由管理员核验后进入 OCR 流程。 |

## 快速启动

```bash
python3 ops/consensus_task_app_server.py
```

启动后打开：

```text
http://127.0.0.1:8090/
```

OCR 引擎依赖具体运行环境。建议通过环境变量配置解释器、模型路径和运行策略，不要在代码中硬编码本地路径。

常用变量示例：

```bash
export OCR_CONSENSUS_PORT=8090
export OCR_ENGINE_PARALLEL=aggressive
export OCR_SHADOW_ENGINES=ppocrv6_small
export OCR_PARALLEL_SHADOW_ENGINES=0
export OCR_ROI_ID_FALLBACK=0
```

## 隐私与发布策略

本仓库只应包含源代码、模板和文档。

不要提交运行时数据、上传图片、OCR 结果 JSON、生成后的 dashboard、基线数据库、代理脚本、本地环境文件、内网地址或客户特定过程报告。

发布前请检查 [PUBLICATION.md](PUBLICATION.md)。

## 当前状态

OCR Consensus 当前定位为“结构化抽取 + 多模型共识 + 基线管理 + 人工审阅”的工作台，适合用于 OCR 质量评估、规则迭代、批量审阅、基线比对和人机协同复核。

正式生产使用前，请确认 OCR 引擎部署、访问控制、存储隔离、数据留存、审计日志和部署环境安全要求。
